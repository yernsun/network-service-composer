# Internationalization

[locales.json](../../internal/i18n/locales.json) is the locale authority: en, ja, de, zh-CN, zh-TW, fr, ru and es. Do not maintain a second runtime language list.

Use shared catalogs in internal/i18n/catalogs and frontend-specific catalogs in frontend/src/shared/i18n/locales. User-visible messages use translation keys; English keys, nonempty values and named placeholders must match across locales. Preserve valid Unicode. Review translation meaning; passing structural checks or copying English into another locale is not translation acceptance.

Frontend messages are generated at build time. Do not hand-edit generated catalogs or generated API declarations. Keep machine error code, params and errors[].pointer stable; localized title/detail is display text, never an automation contract. Do not translate or expose secrets and raw confidential diagnostics.

Official market README and core/operations manuals must cover every configured locale. Update source revision hashes and translation acknowledgements only after reviewing the translations. Source changes invalidate old acknowledgements. Third-party markets may declare fewer languages; the reader must show the actual fallback language, preserve document identity during language changes and leave the UI locale unchanged. Keep document HTML inert and remote images unloaded.

Run frontend i18n checks, backend i18n/API tests and the official static market build. Add behavior tests for changed fallback, missing content, invalid links and stale translation handling. See [market format](../../docs/marketplace-manifest.md).
