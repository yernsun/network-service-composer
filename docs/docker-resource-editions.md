# Docker Config and Secret editions

Docker Configs and Secrets are immutable Swarm resources. The community edition manages individually named objects in one authenticated Swarm cluster. It can create an object, list metadata and current Service references, select an external reference in a Compose source, and safely remove an unused NSC-owned object. The actual Docker name is the administrator's input name. Creation is not an edit: changing bytes requires a new name and an explicit deployment. Externally created objects are read-only. Contents are never returned by the API, displayed after creation, or retained in the long-lived resource record.

The community edition has no virtual aliases, version history, content update, or automatic rotation and redeployment for either Configs or Secrets. These are commercial-only capabilities. The API server must enforce the edition boundary; hiding a button in the UI is insufficient.

The future commercial implementation belongs in a separate private module and image. It may treat an adopted community object with the exact logical name as version 1. Later versions use physical names such as `example.key.v000002` while the Compose source keeps `example.key` as its logical reference. An update freezes the set of consumers, then deploys them one by one. A failed consumer keeps its previous physical object; the operation reports partial completion and allows retry. It must not claim an automatic global rollback across applications. This document records an interface boundary, not an implemented license or commercial service.
